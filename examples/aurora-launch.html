01 / The Problem

漂亮与可改，
过去只能二选一

截图式方案交付的是图片，模板式方案交付的是牢笼。真正的交付物应该是内容本身。

图片

改不动

整页截图，字号、颜色、错别字全部冻结，二次编辑等于重做。

模板

装不下

固定版式只能容纳固定结构，一旦内容变化就要推倒重排。

手工

做不快

每一页都靠人力对齐、调间距、数像素，20 页耗掉一整天。

02 / The Method

三条流水线，一条比一条短

STEP 01
用 HTML 排版 网格、弹性盒、渐变、圆角——浏览器里怎么排，幻灯片里就怎么排。
STEP 02
纯 Python 计算 真实字体度量驱动换行，不启动浏览器、不截图、不联网。
STEP 03
写出原生 PPTX 文本、形状、图标、表格全部是 PowerPoint 原生对象。

交付前

  • 字体 不是图片，双击即可换字
  • 图标 转成矢量形状，可配色可缩放
  • 表格 仍是表格，可以直接填数

交付后

  • 备注 写在 aside 里，自动进入演讲者视图
  • 主题色 与 PowerPoint 主题联动，换色全局生效
  • 单选 每个元素独立可选，改一处不动全身

03 / Performance

快，是因为什么都不用等

构建耗时分布

HTML 解析
6ms
样式计算
11ms
布局排版
41ms
写出 PPTX
27ms

9 页演示，含图标矢量转换与主题写入，总计 85ms。

对比

  • 浏览器渲染 + 截图方案：依赖 Chromium，冷启动 3–8 秒
  • 模板填充方案：版式固定，越用越像同一份 PPT
  • Aurora 流水线：无浏览器、无网络、无隐藏服务

一句话

把「渲染」换成「计算」，是这份流水线快一个数量级的全部原因。
